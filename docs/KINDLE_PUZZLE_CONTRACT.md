# Pinned Kindle puzzle contract for Kobo parity (Task 00)

**Normative reference:** [Kindle `docs/PUZZLE_FORMAT.md` at `80eaf892fe0c7a96e3ba603e25ee3af57e3d93c8`](https://github.com/abavelski/kindle-chess-puzzles/blob/80eaf892fe0c7a96e3ba603e25ee3af57e3d93c8/docs/PUZZLE_FORMAT.md) in `abavelski/kindle-chess-puzzles`. That file's Git blob SHA-1 is `1076d9a09087b7e0b56b1c8d8fd6e54f0f81dcfa`. This document summarizes compatibility-critical decisions; **the pinned upstream document is authoritative**, not the mutable upstream default branch or a new Kobo schema.

## Scope and reproducibility

The unmodified upstream bytes live under `tests/fixtures/kindle-parity/`. Its `manifest.json` records relative upstream paths, pinned revision, Git blob IDs, SHA-256 byte hashes, sizes, expected-valid/invalid labels and each invalid fixture's intended violated invariant. `tests/kindle_parity_corpus.rs` verifies the complete named set, labels, hashes, JSON decoding, the manifest identity, and availability to ordinary host `cargo test`. This task does **not** implement the rich parser or assert the invalid examples are rejected by Kobo; that belongs to Task 02.

The existing Kobo `examples/puzzles.json` is a separate legacy example, pinned by SHA-256 in the manifest/test. Imports never replace it, other examples, generated collections, device files or `progress.v1`. A future fixture update must explicitly compare its upstream revision and hashes and update the manifest/test as a reviewed change.

## Frozen compatibility details

- **Collection identity/order:** collection root remains `version: 1` with a nonempty ordered `puzzles` array. IDs are unique, nonblank, durable per collection; optional trimmed `title` is for picker display. Keep each collection's puzzle order and node/child order as supplied—**never sort analysis nodes or children**. Ignore unmodeled metadata, including optional root content revision.
- **Legacy solving path:** each puzzle requires a six-field `fen` and nonempty `solution` array of lowercase UCI moves. Position's FEN active color determines the solver; each `solution` array alternates solver move, automatic opponent reply. Promotion suffix is lowercase `q/r/b/n`, castling uses coordinate UCI, origin and destination differ. **Only `solution` is graded**; analysis alternatives and sidelines are read-only and must not change progress, correctness, or stored files.
- **Additive puzzle metadata:** optional `topic` (Unicode, including Cyrillic/newlines) is presentation only; missing, null or non-string values have no displayed topic. `description` remains an optional legacy plain string; `description_content` adds structured spans. Optional `difficulty` is a string or number.
- **Rich tree shape:** optional `analysis: {"version":1,"root":<id>,"nodes":[...]}` keeps root collection version 1. The nonempty node array has unique nonblank IDs. Its single root must have a `fen` exactly string-equal to the puzzle FEN and no `parent`, `move`, `role`, or `nags`. Each non-root node has exactly one existing parent, one `move` with nonempty SAN plus valid UCI, its own complete post-move six-field FEN, and appears once in its parent's children. Edges agree both ways, reach all nodes, and contain no cycles. FEN is **stored**, never regenerated from SAN/UCI by the renderer; this contract does not require a chess legality engine.
- **Roles and main path:** non-root roles are `main`, `alternative` or `sideline` (omission defaults to `sideline`). At most one `main` child per position; following only those children from root must produce exactly the legacy `solution` UCI sequence, with identical length and promotion suffix. No disconnected `main` role is valid. Other roles are browse-only.
- **Defaults and authoritative content:** missing `comment` becomes `""`, missing `nags`/`children` become `[]`. Missing node `content` is one noninteractive text span containing the nonempty `comment`, otherwise `[]`; missing `description_content` uses the same projection from nonempty `description`. **Present empty** `content: []` or `description_content: []` stays empty and overrides the plain-text fallback. Plain projections need not be text-identical to structured spans.
- **Structured links:** `text` spans contain exactly `type` and a nonempty `text`; `move_ref` spans contain `type`, an existing **non-root** `node` ID, and optional nonempty `label`. No extra or unknown keys, invalid types, empty required values, dangling or root targets. Missing label displays target SAN; labels are otherwise kept verbatim. Only explicit `move_ref` is clickable: prose resembling SAN/UCI must never be auto-linked. Explicit PGN authoring directives `[%move_ref uci/path|label]` are resolved offline by the Kindle converter, not by Kobo.
- **NAGs and display:** optional `nags` is a list of non-negative integer PGN glyph IDs; 1–6 render as `!`, `?`, `!!`, `??`, `!?`, `?!` attached to SAN, others as `$N`. Preserve numeric values and explicitly authored reference labels. Comments, variations and NAG order are significant for later inline projection.
- **File size:** phase-two collections are capped at **8 MiB = 8,388,608 raw UTF-8 bytes before JSON parsing**. The older 256 KiB policy is **not** the rich-format limit. Kobo's currently deployed 256 KiB Cobalt-store transport is a separate, unresolved Task 01 implementation concern: this contract-and-fixtures task does not claim large-file loading works.

The valid fixtures cover black-to-move promotion, FEN/SAN/UCI, role/default behavior, explicit/unlinked prose, and nested ordered variations; every `invalid-*.json` is intentionally parseable JSON with one category of *rich semantic* contract violation, not a malformed-JSON test. See each entry's `invariant` in the manifest and the pinned Kindle fixture README.
