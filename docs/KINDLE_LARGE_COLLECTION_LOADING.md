# Kobo Kindle-sized collection loading (Task 01)

The pinned Cobalt SDK/runtime commit remains `ff4ec9950e178243807082bf818e42c8538d080e`. Before packaging, `scripts/prepare_cobalt.py` applies `scripts/cobalt_collection_range.py` **idempotently** to the *exact pinned* local Cobalt checkout. It patches only the policy store and the device/host dispatch routing for a read-only, namespaced `StoreRequest::ShelfRead` request (`eink-chess-collection-read-v1-puzzles*.json`). **Rebuild/redeploy kobod** with the usual `scripts/build_deploy_kobo.sh` flow; packaging an unpatched kobod does not enable large collection loading. Updating the Cobalt pin requires reviewing the patch anchors and rerunning host tests before packaging. If the anchors change, preparation fails instead of silently producing a device incapable of reading large books.

The provider reads only `puzzles.json` and `puzzles-<name>.json` from that application's existing keyed state directory; it rejects invalid Cobalt keys/traversal. It cannot write, rename or create any collection. Its response is bounded to 64 KiB and uses the **existing** Cobalt shelf wire message. The global `MAX_STORE_VALUE` (256 KiB), shelf storage, `MAX_FRAME_LEN` (8 MiB) and progress record are untouched. Old unpatched kobod interprets the namespaced read as an absent shelf blob; the app shows an explicit runtime-capability error. Small collections continue using the original Cobalt `store().load` path.

The application detects the old store's `TooFull` result and starts the range reader; the entire collection is assembled with a fixed 8 MiB cap, strictly checked size/offset/exact chunk length, and a second pass that compares every returned byte against the first. This catches missing/duplicated/out-of-order/short chunks, size changes, and replaced/edited books during loading (except a file deliberately changed and reverted between reads). A failed selection never activates an incomplete collection or changes progress. The full JSON and UTF-8 check remains at the parser boundary. Files above the cap are rejected; exact 8 MiB is permitted.

Metadata enumeration continues to use bounded `store().list()`, one candidate at a time. Small collections retain their fully parsed title/validity metadata. Large collections are probed with only one 64-KiB range and presented initially by filename; until selected their full validity and embedded title are unknown. A selected book is fully validated before activation. Initial collection loading skips candidates that fail to parse and tries the next neighbor, without rewriting any files.

Verification: `cargo test` and `cargo fmt --all -- --check` exercise the collector's host simulations. `python3 scripts/prepare_cobalt.py /path/to/pinned/Cobalt` prepares the runtime patch; the full Cobalt simulator and actual hardware install remain separate gates. Never mark physical-device checks complete based on host tests.
